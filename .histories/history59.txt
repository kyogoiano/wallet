# 10. The transaction logic needs one correction for deposits/withdrawals

The plan says:

```text
TransferFundsUseCase
DepositFundsUseCase
WithdrawFundsUseCase

if (!sourceAccount.tenantId().equals(command.tenantId()))
```

and then:

```text
if (!targetAccount...)
```

But deposit and withdrawal don't necessarily have both source and target accounts.

So the architectural rule should be:

```text
Transfer:
    source tenant == command tenant
    target tenant == command tenant

Deposit:
    target/account tenant == command tenant

Withdrawal:
    source/account tenant == command tenant
```

The underlying principle is already correct; the pseudo-code just needs operation-specific wording.

# 11. Performance target: P99 < 50 μs

I'd soften this.

The plan says:

> HMAC authentication and credential resolution ... `P99 < 50μs`.

That's a useful benchmark target, but it isn't an architectural invariant.

HMAC involves:

* request-body hashing
* canonicalization
* HMAC
* header parsing
* potentially body buffering

and the actual result depends heavily on payload size and runtime conditions.

I'd change:

```text
P99 < 50μs
```

to:

```text
Target: P99 < 50 μs for authentication overhead
excluding network I/O and payload acquisition, measured with
representative payload sizes.
```

or make it a benchmark acceptance target rather than a hard functional requirement.

This is consistent with how we treated the group-commit SLO in 000.9.2.
