### 1. 🔴 `TASK-3.2.7`: não devemos assumir `AccountUseCase.find()`

Este é o ponto mais importante.

A task diz:

> Resolve `userId` via `AccountUseCase.find(walletId).userId()` estritamente para satisfazer existing `SaveCashflowProfileCommand` contract

Isso é aceitável **somente se esse for realmente o contrato existente em `goals::api`**.

Como o próprio PLAN deixou isso como ponto a verificar, eu não deixaria a task afirmar isso como fato arquitetural antes de verificar o código.

Melhor:

```text
- [ ] TASK-3.2.7 [MUST]: Implement unit tests in CashflowForecastingServiceTest verifying:
  - Query active subscriptions via SubscriptionDao.findByWalletId(tenantId, walletId, ACTIVE).
  - Non-locking balance read via BalanceUseCase.getBalance(walletId).
  - Resolve the user identity required by the existing goals::api
    SaveCashflowProfileCommand contract using the existing public API.
  - Query existing profile via the existing goals::api contract and preserve
    minimumSafetyBuffer and monthlyIncome.
  - Save profile via the existing goals::api contract idempotently.
```

E acrescentaria no `TASK-3.2.7`:

```text
No new identity-resolution API, repository, or direct Goals persistence may be introduced.
```

Isso evita o Antigravity inventar uma API só para satisfazer a task.

### 2. 🔴 `TASK-3.2.5`: "never added together" está conceitualmente estranho

A task diz:

> `L_H` and committed are never added together

Isso é correto como **regra de shortfall**, mas não como propriedade do engine.

O que queremos é:

```text
Shortfall_H = max(0, L_H - currentBalance)
```

e não:

```text
max(0, (L_H + monthlyCommitted) - currentBalance)
```

Portanto eu mudaria para:

```text
- [ ] TASK-3.2.5 [MUST]: Implement unit tests in CashflowForecastingEngineTest
  for monthly committed normalization:

  - INSTALLMENT is excluded from perpetual monthlyCommittedExpenses.
  - INSTALLMENT remains included in discrete forward liability L_H while
    the installment is active.
  - Monthly committed expenses and forward liabilities are exposed as
    separate projection dimensions.
  - Shortfall_H is calculated exclusively from L_H and current balance;
    monthlyCommittedExpenses MUST NOT be added to L_H.
```

Isso fica muito mais preciso e alinhado com o PLAN.
